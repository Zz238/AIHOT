研究日期：2026-10-13；安徽查询源补充核实日期：2026-10-14。基于用户提供的方向，核实少量公开页面，已完成本地离线解析原型；没有启动持续采集、搜索订阅、付费模型、通知或生产入库。用户给出的 4.8 元/公斤等 JSON 是结构示例，未当作真实报价。

## 商务部样本的关键边界

- 日报是**市场批发监测报价**。原页没有说明市场内采样数、具体均价方法或单摊成交记录，不能称居民零售价或单摊实价。
- 表格地区只有“安徽省”。合肥来自精确市场名和市场 ID 的人工核实映射；其他安徽城市不算合肥。`enterid=3994` 是该站市场 ID，不是本系统地区代码。
- 商品标题为“西红柿”，未标规格。不能自动改成“普通番茄”；现有字典还区分圣女果、水果番茄，这条应进入待映射/审核。
- 当日 4.3 元/公斤可按 500g 市斤换算成 2.15 元/斤，仍保留原值与原单位，且标明批发参考、实际日期与单一发布主体。
- 页面环比写 -2.33；按常见的 `(本期-前期)/前期` 计算会为约 +2.38%。尚未核实其符号与基期约定，保留源字段而不直接发布涨跌。
- 大屏页显示日期由浏览器“昨天”计算；图表标题窗口可到 10-12，但实际节点只到 10-11。观测日只用日报明确日期及真实图表节点，缺失日不补齐。
- 本轮目录发现 40 项、39 个唯一 ID，并有洋葱/蒜头共用 `170100` 的异常。每个商品必须交叉核对页面标题，不能批量盲导目录。
- 本轮 `cif.mofcom.gov.cn` 与 `pfsc.agri.cn` 的 robots 请求返回 404；这没有证明持续采集、转载或商用许可已获得。安徽价格信息网和瑶海政府站的 robots 本轮未能核验。商务部页面列示版权与联系邮箱 `cif@ec.com.cn`，使用范围仍待核对。

## 已完成的离线验证

`backend/mofcom-preview.ts` 与 `scripts/preview-mofcom.ts` 只解析本地 UTF-8 HTML，核对来源 URL、标题、单位、日期、表头和精确周谷堆市场行。输出候选、标准化预览和审核限制；不连接数据库，不发网络请求，也不调用模型。

测试片段位于 `tests/fixtures/mofcom-tomato-excerpt.html`，是本次公开历史事实的最小重建片段，不是完整网页，也不会被初始化脚本导入。离线运行方式：

```sh
node modules/market-price/scripts/preview-mofcom.ts modules/market-price/tests/fixtures/mofcom-tomato-excerpt.html 'https://cif.mofcom.gov.cn/cif/seach.fhtml?commdityid=170120'
```

此命令实跑退出码 0：仅输出 1 条 2026-10-11 周谷堆西红柿候选，4.3 元/公斤换算为 2.15 元/斤；规格空、商品未映射、状态 `pending`，上游原记录 ID 为空，本地预览键仅用于预览。原前日价和环比只保留为证据。

还使用研究时取得的完整公开 HTML（65,788 字节）验证了真实页面结构：检查 108 条全国市场行，仅筛出 1 条周谷堆候选，日期、原价、单位、标准化价格和待审核限制与上述结果一致。完整网页只保存在本地验证文件中，未提交仓库，也未写入运行库。

4 项针对性测试全部通过：市场隔离、未知规格待审核、观测日期来源、异常日期/单位/来源/结构拒绝。模块类型检查通过。复现命令：

```sh
node --import ./tests/standalone.ts --test modules/market-price/tests/mofcom-preview.standalone.test.ts
npx tsc -p modules/tsconfig.json
```

现有通用 HTML 采集器按行字段读取，而这个来源的商品、单位和日期在页头，需要专门适配。此实验解析器**尚未注册为后台自动采集器**，不能只在后台填网址就宣称完整接入；取得许可、核实口径和商品/市场映射后再注册。

## 口径与来源质量

保留三条分别展示的轨道：市场批发参考、明确口径的地方零售监测、经审核的用户购买记录。商品规格、地区/区级范围、市场、价格类型、观测日期、统计周期及采样方法一致后，才讨论同轨道内的统计。

政府监测均价、月均价和单个摊位报价不是相同统计对象；指数没有“元/斤”单位。暂不把它们塞进同一个每日单点样本池，不采用“官方 40% + 市场 30% + 用户 30%”跨口径混合价。否则混合值既不能说明批发基准，也不能说明居民实际购买价。

现有 `market_sources.trust_score`（0–1）和 `publisher_key` 可用于审核门槛与独立主体计数，先不另建重复的评分表。来源性质（政府/市场/文章/用户）与采集方式（HTML/JSON/RSS/推送）是两种分类；不会向原新闻 `sources.kind` 添加政府等枚举。

政府身份是核验线索，不能代替字段完整性、更新时间和错误率。实验先记录可核验率、复采成功率、日期延迟、规格映射通过率及人工审核耗时，再确定分级规则。用户信誉不能仅靠“连续上报 10 次”升权；认证主体、重复凭证和异常记录仍需检查，现有用户记录保持待审核。

同一个周谷堆报价被商务部、农业农村部或新闻网站转载，仍可能只有一个上游发布主体。缺少原始记录关系时不把转载增加为独立样本。本来源可以派生本地重放键，但不会把派生键冒充上游提供的原记录 ID。

## 七天实验的建议验收方法

本轮没有创建七天定时任务。持续实验开始前先具备：已核实的使用范围、可访问原页、确定的市场/商品映射、专用实验库及数量/费用上限。公开结构化表先用程序解析；AI 仅处理明确含报价且规则无法可靠提取的文章。

1. 先用 1 个可核验来源、1 个市场和少量商品完成抓取 → 解析 → 待审核 → 已核验 → 同口径汇总 → API。随后增加一个**独立发布主体**，而不是加一个转载网站。
2. 第一天实测每个来源的合肥有效行数、有效商品规格数、实际观察日和单位；商品清单先从可核实的覆盖建立，不直接承诺 100 种。
3. 连续七天分别记录请求/文件数、原始数据行数、合肥候选数、去重后观测数、审核通过数、独立发布主体数及缺失日期。100 篇网页不等于 100 个报价，108 条全国行不等于 108 条合肥行。
4. 已核验同作用域至少 3 个样本及 2 个独立发布主体才生成 P20–P80；否则只展示标明来源的单一参考或数据不足。一个市场多日数据不能满足“当天多个独立来源”。
5. 优先评价可追溯性、口径一致性、持续更新和审核成本。“每天 1000 条原始数据、100–300 条有效价格”目前没有证据支持，只作为待实测目标，不能靠扩搜/转载凑量。

启动市场采集需要总采集开关；原初始化同时保留了新闻演示信源。实验开始前须在专用环境逐一核对参与信源，避免总开关同时启动无关演示采集。当前开关保持关闭，不会因本文件或离线命令打开。

## 需要用户补充的资料

商务部样本和安徽查询源的本地验证目前不需要用户额外提供 Key。用户已补充安徽具体查询链接及截图，且本机查询已成功，不再要求为这个来源寻找 PDF/Excel。剩余主要是持续采集与再发布的可使用范围；安徽网站法律声明明确涉及书面许可和非商业引用限制，详见 [安徽来源说明](market-price-anhui-source.md)。提供网页线索不等于确认采集许可，也不需要向聊天发送账号密码。

用户可从上述政府公开栏目进入具体报告，下载原始附件，直接在当前聊天附上文件及原网页链接；或保存到 `E:/市场价/菜价数据资料/` 后在聊天给出文件路径。只给栏目首页或搜索摘要还不足以核对数值。若已有来源授权或使用条款，请一并提供其公开链接或说明原文；如需询问来源方，用户可使用来源官网所列联系方式，本轮没有代发消息。

商业平台、搜索服务和公众号暂作为发现原文的候选通道。只有在实际选定服务并明确其接口和使用范围后，才说明是否需要官方 API Key；不默认要求购买或给百度、搜狗、公众号配置密钥。
