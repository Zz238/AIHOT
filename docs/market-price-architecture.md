# 菜价雷达：实际实现的架构

本模块基于 AIHOT `931a4eb5edf344b12b9e65f0d039f7c52a2e0792`，独立放在 `modules/market-price/`。后台入口为 `/admin/market/overview`。新闻业务表、`sources.kind`、新闻评分和已发布迁移没有修改；原新闻入口仍然存在。现有 Taro 小程序源码没有改动。

## 模块边界

`module.ts` 声明路由与后台页面，`server.ts` 注册 HTTP、任务、模型步骤、告警和保留策略，`web.tsx` 注册管理导航；通过 `site/modules/{index,server,web}.ts` 接入。工作区、锁文件、Docker manifest 和 Compose Setup 都包含此模块。

| 文件 | 职责 |
| --- | --- |
| `backend/collectors.ts` | 受限 JSON/HTML/RSS 请求、分页和离线解析 |
| `backend/extract.ts` | 中文规则提取、模型回执、逐条证据校验 |
| `backend/normalize.ts` | 规格匹配、单位/日期标准化、质量标记和业务身份 |
| `backend/repository.ts` | 原始观测、修订、审核审计、事务内重算 |
| `backend/statistics.ts` | 去重后样本和独立信源计数、P20–P80 |
| `backend/publication.ts` | 唯一公开读取层；只读已核验样本的汇总 |
| `backend/briefs.ts` | 客观指标和可核验简报、版本复用与失效 |
| `backend/jobs.ts` | 五个持久化队列、定时调度、批次结果和重试 |
| `backend/user-report.ts` | 必须由服务端验证身份的用户上报适配层 |
| `api/routes.ts` | 公开 API、服务端推送和原管理员鉴权后的管理 API |
| `web/*.tsx` | 六类后台页面、历史图和 HTTP 数据加载 |

复用原 `fetchListing`、`fetchRss`、正文提取、SSRF/DNS/重定向防护、`chatJson`、预算及付费请求回执、pg-boss、`adminHandler`、CSRF、`audit`、问题响应和告警总线。没有另建 Redis、Kafka 或认证框架。Web 只通过 HTTP 访问后端。

## 存储和数据流

18 个新迁移 `0090`–`0107` 由原迁移器自动发现，每个文件一条 DDL。13 张业务表分别记录地区、商品、别名、市场、信源、采集任务、观测、不可覆盖的观测修订、日汇总、审核、简报、文章、推送批次；另有任务批次结果表和查询索引。实际表定义以迁移文件为准。

信源 → `market.collect` → 结构化候选/文章 → `market.validate` 或 `market.extract` → 观测与修订 → 按作用域汇总 → `market.brief` → 公开读取层。管理员手动重算使用 `market.aggregate`。审核、更正、撤回在同一事务内立即重算受影响的日期，避免仍向客户端发布旧结果。

五个队列使用原 pg-boss：每批一个任务，失败重试最多 3 次，起始延迟 30 秒并退避，过期时间 600 秒。信源执行持有独立 advisory lock，写入和入队使用同一事务；校验结果按任务与批次身份保存。重放已完成批次不会重复计价或累加成功数。文章处理失败记录错误，队列重试耗尽后需要管理员显式重试。重试全部完成后任务恢复为成功状态。

采集调度每分钟检查到期信源，每次最多 100 个，仍受总采集开关与市场采集开关约束；信源间隔最少 15 分钟。每小时第 15 分钟检查当天有效数据并生成简报，无报价则不创建虚构行情。

## 采集约束

- JSON 支持 GET/POST、点路径字段映射、分页参数；HTML 支持行/字段/日期/下一页 CSS 选择器。每信源最多 10 页，每页间隔至少 250ms，最多 10,000 个候选。
- 信源需要确认使用许可。robots 检查失败时停止，明确禁止的路径不能采集；采用保守的 Disallow 优先策略，可能比站点规则更严格。
- URL、DNS、重定向和响应大小复用原防护。认证配置只引用 `MARKET_SOURCE_*_TOKEN` 环境变量，同源分页才能携带认证。
- RSS 最多读取 100 篇条目。`fetch_article_body` 默认关闭；显式启用后每次最多补抓 10 篇同源、已授权正文，受 robots、SSRF、15 秒单次超时、2MB 正文及 240 秒批次开始预算约束。跨域正文需要单独信源，不自动追抓。
- JS 动态表格、验证码、登录绕过和全站无头浏览器采集没有实现。
- 离线解析预览只处理管理员提供的样本，不写价格表，也不访问外部网络。运行时初始化只创建地区和商品字典，不种报价。

## 标准化、身份和审核

商品名与规格共同匹配，普通番茄、圣女果、水果番茄使用不同 `product_id`。公斤、千克、斤、500 克换算到 `元/斤`（市斤，500g）；盒、袋、把、个只有可核验重量时才能转换。原报价和原单位始终保留。

观测时间、原文发布时间、系统采集时间分别保存。日期按北京时间判定；拒绝不存在或未来日期，缺失/含糊日期进入待审核。正文的分段日期逐段识别，发布时间不能替代观测日期。历史样本只参与其实际观测日期的汇总。

业务身份包含信源、原记录 ID（缺失时使用 URL）、标准商品、原规格、地区、市场、价格类型和观测日期。同 URL 不同日可独立存储；同日同记录原文变化追加修订；相同内容重放不计数。来源变化后的报价重新校验，不继承人工通过。

转载去重还包含 `publisher_key`。镜像必须配置同一发布主体和一致的 `source_record_id`，才能认定为同一报价；缺乏共同记录身份时，不凭不同 URL 猜测重复。应在启用前正确配置发布主体；已使用信源的主体/地区发生实质变化时应新建信源并审核旧记录，系统不自动批量迁移历史身份。

可信度低于 0.8、未知商品/地区/市场、信源地区不一致、日期缺失、未知价格类型、AI 或用户证据、相对同作用域历史价格变化超过 50% 时进入待审核。非法价格、无法换算单位和未来日期拒绝。审核需原管理员会话、CSRF、原因及期望版本；并发旧版本返回冲突。单位更正需单位证据，原始记录不可覆盖。撤销只作用于最后一次审核决定，保存完整审计。

## 聚合与简报

作用域严格区分地区、标准商品及规格、市场报价身份、价格类型、日期。先按报价身份去重，至少 3 个有效样本且至少 2 个独立发布主体才生成 P20–P80 区间。否则上下界为空，保留真实计数、最小/最大值、中位数及质量状态；单个样本可作为明确标注的单一信源报价。它不代表全市零售均价。

每次输入修订改变汇总版本。更正或撤回会使本日与次日涉及前日比较的简报失效；简报生成事务再次核对输入，避免并发覆盖新结果。程序计算价格、覆盖、样本数和可比较涨跌；可选模型只选择三个预先审核的引导句，不能自由生成数字、预测或供需结论。没有数据返回空，样本不足明确说明不足。

模型只用于规则无法可靠提取的含价格文章，原文无报价返回空；结果通过严格 Zod Schema 与数字、单位、日期、产品名、证据子串校验。规则提取的文章报价也进入人工证据审核。模型通过 `modelFor` 注入并复用预算、回执，不进入新闻多轮评分。匿名 GET 永远不请求模型。

## 安全、费用与保留

公开 API 不输出待审核数据、原始载荷或密钥。推送使用至少 32 位服务端 Bearer Token、512KiB 请求体、每批最多 100 条、幂等键及限流。用户上报适配器要求宿主提供真实服务端会话验证，客户端自称的 openid 不构成认证；上报始终待审核，不能覆盖已核验观测。

限流是进程内计数，不是集群全局额度。保持 Compose API 内网部署，经 Web 代理访问；多实例或直接对公网暴露 API 时必须在可信入口另设限流和代理头规则。

总览显示真实任务数量、抓取页面和耗时；模型费用来自原回执，未知人民币成本显示未知，不伪装为零。告警接入原失败/恢复总线，关闭采集时不误报；本次开发没有向外发送通知。

默认 180 天保留策略只清理已处理观测投影中的 `raw_payload`。修订证据和文章原文仍保留，以维持审计；这不是“到期删除全部正文”的实现。有明确合规删除要求时，需另行确定版本证据保留政策。

项目保留 AIHOT 开源许可证和来源说明；菜价雷达名称用于自有业务后台，未新增上游商标或品牌素材。部署及实测限制见 [部署说明](market-price-deployment.md) 与 [验收记录](market-price-verification.md)。
